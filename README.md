# LD7182 AI for IoT: TinyML Air Quality Classifier (ESP32-S3)

An AIoT prototype that classifies air quality as **Good / Moderate / Poor** from four gas readings
(CO, NO2, SO2, O3). A small decision tree is trained in Python, exported to C, and runs **on the
ESP32-S3**, which also uploads readings and the predicted class to ThingSpeak.

## How the system works
1. **Label:** PM2.5 is binned using US EPA 2024 bands (Good <= 9.0, Moderate 9.1-35.4, Poor > 35.4 ug/m3).
2. **Features:** CO, NO2, SO2, O3 only. PM2.5 and PM10 are excluded because the label is derived from PM2.5.
3. **Evaluation:** leave-one-city-out (pooled), because random splits overstate performance for a device placed in a new city.
4. **Model:** decision tree, depth chosen by cross-validated macro F1; exported to C as nested `if/else` (no libraries).
5. **Device:** the ESP32-S3 reads four analogue inputs (potentiometers standing in for gas sensors), runs `aq_predict()`, lights an LED, sounds a buzzer for Poor, and uploads to ThingSpeak.

## Run the notebook
```
python -m venv .venv
.venv\Scripts\activate          # Windows (macOS/Linux: source .venv/bin/activate)
pip install -r requirements.txt
```
Open `Air_quality.ipynb` in VS Code or Jupyter, select the `.venv` kernel and run all cells.
Running it regenerates `aq_model.h`. The optional gcc check is skipped automatically if gcc is not installed.

## Run the simulation (Wokwi)
1. Create an **ESP32-S3** project at wokwi.com.
2. Replace `diagram.json` with `firmware/diagram.json`.
3. Add `firmware/aq_model.h` as a new file, and paste `firmware/sketch.ino` (or `sketch_thingspeak.ino`) into the sketch.
4. For cloud upload, create a ThingSpeak channel with five fields (CO, NO2, SO2, O3, AirQualityClass) and put **your own Write API Key** in `TS_WRITE_KEY`. **Never commit a real key.**
5. Press Run, open the Serial Monitor and move the potentiometers.

The potentiometers cover 0 to the 99th percentile of each pollutant (CO 3534, NO2 110, SO2 173, O3 212), in the same units as the dataset.

## Limitations
- Sensors are simulated with potentiometers; real gas sensors would need calibration.
- Six cities and one year of data; performance varies by city.
- The ThingSpeak upload skips TLS certificate validation (simulation only).
